## 1. 최종 목표 (사용자의 말 그대로의 의도)

- **사용자는 마스터 AI와만 소통한다.** 소통 시점은 **처음의 명세 단계**와 **마지막의 배포 단계** 두 곳이다.
- 그 사이(기획, 개발, QA, 위키)는 **마스터 AI가 자동으로 진행**한다. 정말 중요한 사항이 아니면 사용자에게 묻지 않는다.
- **마스터 AI는 Claude**다.
- **비용 때문에, 기획과 개발 등 대부분의 작업은 Codex가 주력으로 한다.** 검수는 Claude가 한다. 작업 규모와 관계없이 계획과 코드는 Codex가 쓴다(2026-10-20 결정. 비용 문제가 보이면 다시 정한다).
- 구독 플랜의 사용량 안에서 운영한다.
  - Codex는 2026-10-10에 ChatGPT Pro(계정 표시 `prolite`, 주간 한도 창 하나)로 올렸다.
  - Claude 요금제가 바뀐 기록은 저장소에 없다(처음 계획은 Claude Pro에서 Max로 올리는 것이었다).
- 분야와 무관한 범용 멀티 에이전트 워크플로우다. 주 용도는 로블록스 게임과 데스크톱 프로그램이고, 웹사이트와 영상(코드 기반)은 이후 확장한다. 분야별 세부 환경은 "도메인 프로필"로 분리한다.
- 사용자는 외주 작업도 한다. 프로젝트 사이에 정보가 넘어가지 않아야 한다(5절 Codex 메모리 차단).

### 목표로 하는 사용자 개입 지점

| 시점 | 사용자가 하는 일 |
|---|---|
| 명세 | 마스터와 질답, 명세 승인. 작은 결정은 마스터가 추천안으로 정하고 명세서의 "가정" 목록에 적는다. 큰 작업이라도 계획 검토는 기본으로 하지 않는다. 계획을 보고 싶으면 명세 머리말에 `계획 검토: 요청`을 넣는다. 측정 시험이면 `측정: 예`를 넣고 Claude 사용률 시작값을 알려준다 |
| 중간 | 정말 중요한 문제가 생겼을 때만 (되돌릴 수 없는 작업, 보안 관련, 작업 공간 밖 영향, 계획이 망가진 경우). Codex 한도·시간 초과로 멈추면 새 세션에서 "이어서 진행"으로 재개한다 |
| 배포 | 최종 QA("사람 확인" 항목만 직접 확인)와 병합 승인. 측정 시험이면 사용률 끝값도 이때 알려준다. **main 병합은 사용자 승인 뒤 AI가 로컬로 한다. GitHub push는 사용자가 직접 한다** |

## 2. 출발점과 큰 방향

- 출발점은 유튜브 영상(youtu.be/woSiT_kytXo)의 에이전트 워크플로우다: 마스터 AI, 기획 → 개발 → 독립 QA → 위키, 작업자-검수자 쌍, 교차 모델 검수, 작업별 기록.
- 처음부터 새로 만들지 않고, **검증된 오픈소스 하네스 Superpowers를 골조로 삼아** 영상에만 있는 좋은 요소를 얹는다.
- **Superpowers 원본 파일은 수정하지 않는다.** 바꿔야 하는 단계는 우리 스킬로 만들어 대체한다 (업데이트 시 덮어써짐 방지, 원인 추적 용이).
- 이전에 만들던 SDD 파이프라인과 Claude/Codex 토론 프로토콜은 전면 폐기했다.

### 비교표 밖의 주요 결정

- **도메인 프로필:** 분야별 QA 도구, 테스트 명령, 규칙을 프로필로 분리. 처음 한 번 마스터와 함께 만들고 사용자 승인 후 Git에 고정해 재사용 (즉석 생성 금지). 첫 프로필은 로블록스(공식 Script Sync + Studio MCP).
- **새 프로젝트 생성 자동화:** 마스터와 짧은 질답 → 스크립트가 폴더·템플릿·Git 설정 → VS Code 새 창 + project-brief로 맥락 전달. 설계 문서는 claude.ai 프로젝트 지식의 "새-프로젝트-생성-자동화-설계.md". 아직 구현 전.
- **로컬 LLM:** 파이프라인 밖의 독립 도구로 나중에 추가 (사전 정의 프롬프트 + 호출 스크립트). "큰 입력 → 작은 출력" 작업만 (로그 요약 등). 보조 PC(RTX 3080)에 LM Studio 서버.
- **사용량 기록:** 가볍게. 기능당 한 줄(`workflow/usage-log.md`). 호출별 Codex 기록은 진행 기록 폴더의 `codex-calls.jsonl`.
  - Codex는 하위 에이전트를 포함한 토큰으로 비교한다. 주간 한도 퍼센트는 참고로만 적는다.
  - Claude 사용률은 명세 머리말에 `측정: 예`가 있을 때만 묻는다. 그 밖에는 Claude 칸을 `-`로 둔다.
- **Codex 설정 고정 (2026-10-20):** 래퍼가 쓰는 프로젝트 Codex 설정(`.codex/config.toml`)에서 모델·추론 강도(워크플로우 설정 파일 값)를 고정하고 메모리(읽기·생성)와 외부 연결 도구를 끈다. 사용자 Codex 설정이 바뀌어도 시험 조건이 바뀌지 않게 하고, 프로젝트 사이 정보를 차단하기 위해서다.
- **저장소:** LLM_WorkFlow와 각 프로젝트는 별개의 Git 저장소. 모노레포는 쓰지 않음 (AI 맥락 오염, 권한 정책, 브랜치 혼재, 외주 납품 문제).

## 4. 핵심 원칙

1. **연결선은 코드로 지킨다.** 프롬프트(규칙 문장)로만 지키는 관문은 새어 나간다. 중요한 관문은 스크립트, 훅, 차단 규칙으로 강제한다 (그래프 엔지니어링의 "어떤 결정을 모델에게 맡기지 않을 것인가").
   - 지금 관문은 세 종류다. 문서에서 섞어 쓰지 않는다.
     - **코드 강제:** 환경·설정·버전·한도 확인, 보고 형식과 실제 변경 대조, 커밋 파일 선택, 보호 경로 사후 거부, 경로 링크·경계 검사.
     - **문장 관문:** 스킬 진입, 검수자의 읽기 전용, TDD, 검수 승인과 수정 상한, main 커밋 금지.
     - **경고 전용:** 네트워크·위험 명령·하위 에이전트 탐지.
   - 검수·QA·병합 관문의 코드 강제는 4단계에서 한다.
2. **쓰기는 한 모델(Codex), 검수는 다른 회사 모델(Claude)이 깨끗한 맥락에서, 읽기 전용으로.**
3. **실패하면 멈춘다.** Codex 호출이 실패하거나 한도에 걸리면 Claude가 대신 구현하지 않고 멈춰서 보고한다. 판단 근거가 없으면 실패로 처리한다. **확인 실패를 통과로 읽지 않는다:** 읽지 못한 값을 "없음", "0건", "none"으로 바꿔 넘기지 않는다. 알려진 한계(예: 네트워크 미차단)를 "차단됨"으로 요약하지 않는다.
4. **사람의 최종 손은 main과 배포.** main 병합은 사용자 승인 뒤 AI가 로컬로 하고, GitHub push(게시)는 사용자가 직접 한다.
5. **각 단계는 이전 단계가 실제로 잘 돌아가는 것을 확인한 뒤에만 넘어간다.**
6. **복잡도를 경계한다.** 효과가 확인되지 않은 층은 빼는 것도 허용한다.

## 5. 안전장치와 알려진 한계

**안전장치**
- Claude 차단 규칙(`.claude/settings.json`): 강제 push, main push, `git reset --hard`, `rm -rf`, `.env`·`secrets/` 읽기·쓰기, PowerShell 도구 전체, `powershell`·`pwsh`·`cmd`(.exe 포함) 호출, `--no-verify`, `taskkill`(.exe 포함). push와 merge는 "확인" 규칙.
- Git pre-push 훅: main으로의 push 거부 (`core.hooksPath .githooks`, 저장소를 만들 때 한 번 켠다). 사용자만 `git push --no-verify`로 통과.
- 래퍼(`codex-run.mjs`)의 장치:
  - 호출 전 확인: 환경·버전, 샌드박스 설정, 프로젝트 Codex 설정의 실제 적용(`config/read`), 외부 연결 도구 0개, 한도 기준값.
  - 프로젝트 Codex 설정 고정: 모델, 추론 강도, 메모리 읽기·생성 끄기, 외부 연결 도구 끄기, 명령 전용 TEMP·TMP·PYTHONPATH.
  - 보호 경로(`.claude/`, `.githooks/`, `CLAUDE.md`, `.codex/`): git이 보는 변경은 어느 깊이든 대조한다. git이 무시하는 파일까지 포함해 최상위 보호 폴더와 `CLAUDE.md`는 호출 전후 해시로 비교한다. 걸리면 커밋하지 않고 변경을 그대로 둔 채 멈춘다(사후 거부이며 쓰기 자체를 막지는 않는다).
  - 래퍼가 쓰거나 지우는 경로(임시 폴더 정리, `.codex/config.toml`, `.superpowers/sdd/.gitignore`, 작업 폴더, `info/exclude`)는 링크(junction 포함)·경계를 확인하고, 실패하면 멈춘다.
  - 임시 폴더: Python 3.13 보정 모듈과 호출 뒤 정리.
  - 탐지와 경고: 네트워크 명령, 위험 명령(프로세스 종료, 권한 변경, 삭제 우회), 하위 에이전트(토큰도 합산).
- 실제 비밀 정보는 프로젝트 폴더에 두지 않는다.
- 관리자 권한 터미널을 쓰지 않는다.
- 테스트와 오래 걸리는 명령에는 제한 시간. 프로세스는 자기가 띄운 PID로만 끝낸다.

**알려진 한계 (기록됨)**
- Claude 차단 규칙은 Codex에 적용되지 않는다. Codex는 자기 샌드박스와 래퍼 지시·탐지로만 제한된다.
- Codex 샌드박스(unelevated)는 저장소 밖 쓰기와 `.git` 쓰기는 막지만 **네트워크와 프로세스 종료는 막지 못한다.** 네트워크는 공통 지시로 금지하고 래퍼가 탐지해 경고할 뿐이다. 그래서 "push는 네트워크 차단으로 막힌다"고 쓰지 않는다. main 대상 push는 활성화된 pre-push 훅으로 제한되고, Claude의 push·merge는 승인 요청 규칙이 있다.
- Codex 하위 에이전트는 설정으로 끌 수 없다. 공통 지시와 사후 탐지로만 막는다.
- elevated 샌드박스는 보류: 이 PC에서 예전에 Temp 폴더 권한을 손상시킨 이력이 있다. 5단계 전 재검토 시 복원 지점을 만든 뒤 시험.
- 시간 초과로 중단해도 Codex가 실행한 명령은 계속 돌 수 있다. 래퍼가 중단 후 2분 동안 늦은 변경을 탐지해 보고한다. 그 뒤의 변경과 git이 무시하는 경로의 변경은 탐지하지 못한다.
- 사고 사례 3건 (모두 Claude 작업자가 Bash로 작업 공간 밖에 영향을 준 일):
  - `taskkill /F /IM node.exe`로 PC의 node 전체를 종료했다.
  - 상대경로 리다이렉트로 `D:\tmp_unused`를 만들었다.
  - 2026-10-11 비용 개선 구현 중 `mv`의 경로를 잘못 써서 `D:\Work\LLM_Project\sub.tmp.mjs`로 옮겼다가 되돌렸다.
  - 지시문만으로는 막지 못한다는 증거다. Bash 명령의 쓰기 대상 경로를 검사하는 PreToolUse 훅은 자체 개발 결정 때 다룰 후보다(비용 개선 명세 19절).

## 6. 운영 방식

- `D:\Work\LLM_Project\LLM_WorkFlow`는 **항상 main**인 운영 폴더. 설치된 플러그인이 이 폴더를 실시간으로 읽는다. 여기서 직접 수정하지 않는다.
- 워크플로우 개발은 `LLM_WorkFlow-dev` worktree의 작업 브랜치에서 한다. 개발 사본 시험은 `claude --plugin-dir <dev>\plugin` (VS Code 확장에서는 이 플래그를 줄 수 없으므로 터미널 CLI에서).
- **배포 = main 병합**(사용자 승인 뒤 로컬로). 배포 후 운영 폴더에서 연결부 점검(`codex-check.mjs`)을 돌린다. `plugin/` 아래 파일이 바뀌지 않은 배포는 점검을 생략한다. 배포는 작업 마지막에 한 번, 작업을 동시에 둘 이상 돌리지 않는다.
- 배포나 점검 결과를 보고할 때는 기준 커밋을 함께 적는다.
- Claude Code 세션은 반드시 작업할 프로젝트 폴더에서 시작한다 (상위 폴더에서 시작하면 그 프로젝트의 규칙이 빠진다).
- 시간 초과로 멈춘 작업은 새 세션에서 "이어서 진행"이라고 하면 재개 승인으로 본다. 멈춘 뒤 새로 바뀐 파일이 있거나 보호 경로가 바뀌었으면 묻는다.
- Codex 요금제를 바꾸면 워크플로우 설정 파일(`plugin/settings/workflow-settings.json`)에 그 요금제의 한도 기준값을 먼저 넣는다. Codex 모델과 추론 강도도 이 파일에서 바꾼다.
- 버전 고정: 양쪽 Superpowers 6.4.1(커밋 5bf4e78), Codex 플러그인 1.0.4, Codex CLI 0.160.0(2026-10-20 확인), Claude 쪽 자동 갱신 끔. 업데이트는 의도적으로 하고, 그때마다 연결부 점검을 다시 돌린다.
