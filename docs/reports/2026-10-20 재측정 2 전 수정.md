## 1. 명세 경로 (분류 1절 1번)

- 계획 지시 틀(`plan-prompt.md`): 계획 머리말에 `**Spec:** \`<명세 경로>\`` 줄을 그대로 쓰게 했다. 본문이 한국어여도 이름표는 영어로 쓴다.
- 계획 검수 추가 지시(`plan-review-additions.md`) 6번: 이 줄이 없거나, 이름표가 번역됐거나, 경로가 다르면 중요 지적이다. 계획 단계에서 미리 잡기 위해서다.
- 작업 스크립트(`codex-task.mjs`): `run`과 `review`는 이 줄을 읽지 못하거나 그 경로에 파일이 없으면 종료 코드 3으로 멈춘다. 지시 파일이나 진행 기록 폴더를 만들기 전에 멈춘다. "none"으로 넘기는 경로는 없앴다.
  - `ledger`는 막지 않는다. 멈출 때 `멈춤:` 줄을 써야 하기 때문이다.

## 2. Codex 메모리·모델·추론 강도 고정 (분류 1절 2번, 10-19 나중 할 일)

### 2.1 바꾼 것

- 워크플로우 설정 파일(`plugin/settings/workflow-settings.json`)에 `"codex": { "model": "gpt-5.6-sol", "reasoningEffort": "ultra" }`를 더했다. 처음 값은 3단계 시험·재측정과 같다.
  - 값이 없거나, 빈 문자열이거나, 작은따옴표·줄바꿈이 있으면 설정 오류(종료 코드 5)다.
- 래퍼가 쓰는 프로젝트 Codex 설정(`.codex/config.toml`)에 다음을 더했다.

  ```toml
  model = 'gpt-5.6-sol'
  model_reasoning_effort = 'ultra'

  [features]
  apps = false
  memories = false

  [memories]
  generate_memories = false
  use_memories = false
  ```

- 래퍼의 유효 설정 확인(`checkEffectiveConfig`, `config/read`): 기존 외부 연결 도구·명령 환경 검사에 더해 다음을 대조한다. 하나라도 다르면 종료 코드 5로 멈춘다.
  - 모델과 추론 강도가 설정 파일 값과 같은지
  - `features.memories`, `memories.use_memories`, `memories.generate_memories`가 모두 `false`인지
- 연결부 점검 15번(새 항목): 2번(구현과 커밋) 대화의 세션 기록에서 확인한다. 모든 차례의 모델·추론 강도가 설정 값이어야 하고, 개발자 지시에 메모리 안내("## Memory" 절)가 없어야 한다.
- 메모리를 끄는 이유는 두 가지다.
  - 측정: 이전 시험의 기억이 섞이지 않게 한다.
  - 프로젝트 사이 정보 차단: 사용자는 외주 작업도 한다.

### 2.2 확인 실험 (10-20, scratchpad의 임시 저장소)

| 확인 | 결과 |
|---|---|
| `config/read` 유효 설정 | 프로젝트 층이 사용자 층을 덮었다. 사용자 층은 `gpt-6-astra`, 메모리 켜짐이고, 유효 값은 `gpt-5.6-sol`, `ultra`, `features.memories=false`, `use_memories=false`, `generate_memories=false`다 |
| 실제 차례 하나(응답 "OK") | 세션 기록의 `turn_context`는 `gpt-5.6-sol`·`ultra`다. 개발자 지시에 메모리 안내가 없다. 개발자 지시 길이는 19,182자로, 재측정 Task 2의 33,662자보다 짧다(메모리 안내 절이 빠짐) |
| 사용 토큰 | 17,985 (출력 24) |

- 확인 못 함: Codex 앱이 나중에 백그라운드로 기억을 만들 때 이 대화들을 건너뛰는지. 유효 설정의 `generate_memories=false`까지만 확인했다. 재측정 2 뒤 `~/.codex/memories/rollout_summaries/`에 재측정 2 대화의 요약이 생기는지 확인한다.

- 실험 저장소가 신뢰 목록에 하나 더해졌다.
