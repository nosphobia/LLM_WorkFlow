## 요약

- **비용:** Claude 사용량이 크게 줄었다. 같은 구간을 API 단가로 환산하면 다음과 같다.

  | 기준 | 3단계 | 재측정 | 비율 |
  |---|---|---|---|
  | 한도 대기 포함 | $14.34 | $6.11 | 0.43배 |
  | 한도 대기 제외 | $12.56 | $6.11 | 0.49배 |

  - 2단계($7.75)보다도 21% 적다.
  - 구독 사용률은 13% → 15%(2%p)였다. 2단계는 5%p였다.
- **Codex:** 8,945,312 토큰으로 3단계(17,343,473)의 0.52배다. 하위 에이전트는 0개, 한도 멈춤은 0회다. 주간 한도는 7% → 9%다(`prolite`, 참고값).
- **대기:** 측정 구간 안에 1시간이 넘는 대기가 없었다. 3단계는 4번(한도 2, 사용자 2)이었다. 계획 시작부터 최종 보고까지 약 56분이 걸렸다.
- **품질:** 계획 검수 지적 3건을 1라운드에 해결했다. 작업별 수정 루프는 0회다. 최종 검수는 승인되어 최종 수정이 없었다. 테스트 35개가 통과했고, 명세의 종료 코드 규칙을 직접 확인했다.
- **안전:** 보호 파일 변경, 위험 명령, 네트워크 명령, 하위 에이전트, 남은 임시 폴더가 모두 없었다.
- **통제하지 못한 조건 (중요):**
  - **Codex 메모리:** 사용자 Codex 설정의 메모리 기능이 켜져 있었다. 재측정의 Codex 호출 6개가 모두 3단계 시험의 같은 작업 요약을 읽었다. 계획 호출은 3단계 계획 검수 지적과 그 수정 방법이 담긴 요약을 읽었다(5.1절). 3단계에는 메모리 사용이 없었다.
  - **명세 경로 누락:** 계획 머리말이 `**명세:**`(한국어)여서 스크립트가 명세 경로를 읽지 못했다. 모든 구현 지시와 최종 검수 지시에 명세가 "none"으로 들어갔다(5.2절).
  - 그래서 품질 결과(최종 수정 없음, 수정 루프 0)와 그에 딸린 비용 감소(약 $1.56)는 비용 개선의 효과로만 볼 수 없다.
- **자체 개발 전환 결정 기준(9.1):** 1, 2번은 충족이다. 3번(사용량)은 이번 결과로는 충족이다. 4번은 해당 사례가 없었다. 결정에 앞서 메모리 영향을 어떻게 볼지 정해야 한다(7절).
