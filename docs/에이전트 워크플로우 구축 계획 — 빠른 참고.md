# 에이전트 워크플로우 구축 계획 — 빠른 참고

Oct 3, 2026 · @nos

## 문서 목적과 현재 위치

**Superpowers를 골조로 삼고, Codex가 작업하고 Claude가 검수하며, Claude 마스터가 지휘하는 에이전트 워크플로우**를 구축한다. 이 문서는 그 설계 결정과 근거를 빠르게 참고하기 위한 요약본이다.

- 출발점: [참고 영상](https://youtu.be/woSiT_kytXo)의 에이전트 워크플로우 (기획 → 개발 → QA → 위키, 작업자-검수자 쌍, 마스터 AI)
- 기존에 만들던 SDD 파이프라인과 Claude/Codex 토론 프로토콜은 **전면 폐기**하고 처음부터 다시 구축한다.
- 현재 위치: 설계 확정 단계. 아직 아무것도 설치하지 않았다.
- 다음 작업: 1단계 기반 공사 상세 설계

**다른 세션에서 이어가는 법:** 이 프로젝트의 새 대화에서 이 문서 링크를 붙이고 "이 계획에서 이어서 진행하자"라고 요청한다.

| 위키 작성 시점 | QA 통과 후 한 번 | 진행 중 기록은 작업별 진행 기록이 담당 |
| 로컬 LLM | 나중에 추가. 파이프라인과 독립된 도구 | 사전 정의 프롬프트 + 호출 스크립트. "큰 입력 → 작은 출력" 작업만 |
| 사용량 기록 | 기능마다 가볍게 기록 | Claude·Codex 사용량, 수정 루프 횟수 |
| 작업 환경 | VS Code + Git | Claude Code와 Codex 모두 VS Code 확장으로 사용 |

## 전체 흐름과 단계별 역할

사용자는 **명세 승인**과 **병합·게시 승인** 때 개입하고 (큰 작업은 기획 결과 검토도 추가), 그 사이는 마스터가 자동으로 진행한다.

&#91;embedded content: 에이전트 워크플로우 · 6단계, 사람 승인 2곳\]

QA에서 실패하면 개발(필요하면 기획)로 되돌아가 통과할 때까지 반복한다. 개발은 할 일 작업마다 새 Codex 세션이 맡고, 작업이 끝날 때마다 Claude가 검수한다.

| 단계 | 산출물 | 작업자 | 검수자 |
| --- | --- | --- | --- |
| 명세 | 명세서: 구현 범위, 제외 범위, 주의사항 | 마스터 (Claude Opus), 사용자와 질답 | 사용자 승인 |
| 기획 | 개발 할 일 + QA 할 일 목록 | Codex | Claude (명세와 대조) |
| 개발 | 작업별 코드, 테스트, 근거 보고 | Codex (작업마다 새 세션) | Claude (읽기 전용, 명세·기획과 대조) |
| QA | 실제 조작 결과, 캡처 증거, QA 보고서 ("사람 확인" 항목 포함) | Codex (개발 내용을 모르는 새 세션) | Claude (증거로 판정) |
| 위키 | 구조·큰 그림 문서 갱신 | Codex | Claude |
| 병합·게시 | 코드와 위키를 함께 반영 |  | 사용자 최종 QA + 승인 |

명세는 "무엇을 만들지", 기획은 "어떻게 만들지"를 정한다. 위키의 틀(목차)은 기반 공사 때 한 번 정하고, 위키 단계에서는 관련 문서만 갱신한다. 작업 중 실시간 기록은 작업별 진행 기록이 담당한다.

**도메인 프로필:** 이 흐름은 분야와 무관하게 같다. 분야마다 달라지는 QA 도구, 테스트 명령, 분야별 규칙은 도메인 프로필로 따로 묶는다. 프로필은 처음 한 번 마스터와 함께 만들고, 사용자가 승인한 뒤 Git에 고정해 재사용한다. 요청할 때마다 즉석에서 만들지 않는다.

## 개조 계획

원칙: **Superpowers 원본 파일은 고치지 않는다.** 플러그인을 업데이트하면 수정분이 덮어써지기 때문이다. 바꿀 단계는 우리 스킬을 따로 만들어 그 자리에서 대신 쓰게 한다.

**유지 (Superpowers 그대로)**

- 설계 인터뷰와 승인 관문, 계획 작성 규칙, 테스트 먼저 쓰기, 완료 전 검증
- 수정 루프 5라운드 상한과 모델 격상, 4가지 상태 보고, 사람 호출 4조건
- 작업별 Git 브랜치 분리, 병합 절차

**교체**

- 기획·개발의 작업자를 Claude에서 Codex로 바꾼다 (공식 Codex 플러그인 사용).
- Codex에도 Superpowers를 설치해, 4가지 상태 보고와 근거 파일 규칙을 똑같이 지키게 한다.

**추가 (영상에서 가져옴)**

- 마스터 층: 명세부터 위키까지 한 명의 지휘자가 이어서 진행
- 계획 교차 검수: Codex가 쓴 계획을 Claude가 명세와 대조
- 명세서에 "제외 범위" 항목 필수화
- QA 할 일 목록, 화면 QA와 캡처 증거, QA 실패 시 롤백
- 위키와 코드 내 AI 노트 주석
- 과거 작업에 대한 마스터 질의
- 한도 대응: 리셋 시각 예약 재개 + 다른 모델로 넘기기
- 병렬 처리 (로드맵 5단계): 독립 덩어리만 나눠 덩어리별로 전체 파이프라인 진행, 의존성이 겹치면 순차 실행, 끝나면 통합 검증. 도입 전에 한도 대응과 덩어리별 QA 환경 분리를 먼저 확인

**변형 후 추가**

- 상태 보고: 개발 4상태는 유지하고, QA·환경 이벤트(분야별 도구 미실행, 연결 끊김 등)를 새로 정의
- 권한 문제: 마스터의 권한 자가 부여는 금지. 멈추고 사람을 호출
- 기록 보존: Superpowers의 작업 공간을 완료 후 삭제하지 않고 보관 폴더로 옮김. 요청 대화와 원본 로그도 추가 저장
- 모델 배정: Superpowers의 역할·난이도 규칙에 Codex 등급(추론 강도) 매핑을 추가

**보류 (필요가 증명되면 도입)**

- 시드 세션 포크: Superpowers의 작업 지시 파일 방식이 비슷한 역할을 이미 하므로 추가하지 않음. 비용 문제가 실제로 생기면 측정 후 재검토

## 운영 규칙과 안전장치

단계 사이는 자동으로 진행하되, **권한은 사람이 미리 정한 정책으로만 존재**한다. 업계 표준도 매 단계 승인이 아니라 경계 설정 + 결과물이 밖으로 나가는 지점의 사람 검토다.

**운영 규칙**

- 수정 루프: 작업당 최대 5라운드. 1\~3라운드는 같은 Codex 작업자, 4\~5라운드는 Codex 추론 강도 상향 → 그래도 안 되면 Claude Opus 투입. 이후 남은 문제는 마스터가 판정하고 기록
- 상태 보고: 완료 / 우려 있음 / 맥락 부족 / 막힘. 같은 방식으로 재시도 금지
- 근거: 테스트 명령과 출력이 없으면 완료로 인정하지 않음. 검수자는 보고를 "검증 안 된 주장"으로 취급
- 검수 강도: Superpowers 모델 선택 규칙을 따른다. 일반 검수는 Sonnet, 수정한 부분의 재검수는 Haiku\~Sonnet, 작업 전체 최종 검수만 Opus. Claude·Codex 등급 대응표 하나를 규칙 파일에 둔다
- 사람 호출: 되돌릴 수 없는 작업, 보안 관련 작업, 작업 공간 밖 영향(병합·푸시·게시), 계획이 망가진 경우. 그 외는 마스터가 판정하고 기록
- 검수자는 항상 읽기 전용. 지휘자도 코드를 직접 고치지 않음
- 명세 승인 때 제외 범위와 완료 기준을 반드시 확인한다. QA 할 일은 완료 기준에서 직접 뽑는다
- QA 할 일마다 "AI 확인" / "사람 확인"을 표시한다. 사용자는 병합 승인 때 QA 보고서를 보고 "사람 확인" 항목만 직접 확인
- 작업 규모별 경로: 전체 파이프라인은 큰 작업에만 쓴다. 작은 작업은 일반 세션이나 Superpowers의 작은 변경 경로로 처리
- 사용량 기록: 기능 하나가 끝날 때마다 Claude·Codex 사용량과 수정 루프 횟수를 기록 (루프 횟수는 마스터가 진행 기록에서 자동으로 적음)

**안전장치**

- 사람 승인 관문은 Superpowers 방식: 작업 규모별 설계 승인 (큰 작업은 명세 승인 + 계획 검토), 마지막 병합 방식 선택
- 마스터의 권한 자가 부여 금지
- 핵심 관문은 코드로 강제: QA 증거나 검수 승인 기록이 없으면 스크립트가 병합을 막는다
- 모든 작업은 별도 Git 브랜치에서 진행
- 차단 규칙: main 브랜치 푸시, 저장소 밖 파일 삭제, 비밀키 접근, 외부 게시(로블록스 게시 등). 야간 무인 운영 때는 더 엄격하게
- Claude·Codex 연결부: 두 모델은 보고 파일 형식만 공유하고, 도구 버전을 고정한다
- MCP와 플러그인은 공식이거나 검증된 것만 사용
- Claude Code 자동 모드(분류기 기반 권한 승인) 사용

## 구축 로드맵

5단계로 나눠, **이전 단계가 실제로 잘 돌아가는 것을 확인한 뒤** 다음으로 넘어간다. 현재는 1단계 직전이다.

1. **기반 공사:** Git 저장소 템플릿, 규칙 파일, 위키 틀, 권한 정책을 만들고 Superpowers와 Codex 플러그인을 설치한다.
2. **Superpowers 기본형 체험:** 아무것도 바꾸지 않고 작은 기능 하나를 끝까지 만들어 원래 흐름을 익힌다. 분야는 무관하다. 사용량 기록을 여기서 시작한다.
3. **작업자 교체:** 기획·개발을 Codex 작성 → Claude 검수 구조로 바꾸고, 두 도구의 연결부를 집중적으로 테스트한다.
4. **영상 요소와 도메인 프로필:** QA 단계와 증거, 위키, 기록 보존, 마스터 층, 병합을 막는 관문 스크립트를 붙이고, 첫 도메인 프로필(로블록스)을 만든다.
5. **야간 운영과 확장:** 한도 대응을 연결하고, 데스크톱·웹·영상 프로필 확장과 병렬 처리를 도입한다.

로컬 LLM 도구는 파이프라인과 독립적이어서, 위 단계와 관계없이 필요할 때 추가한다.
