# Codex 연결부 탐색 보고서

2026-10-05 · 3단계(작업자 교체) 설계 전 탐색

## 목적과 방법

3단계에서 Claude 마스터가 공식 Codex 플러그인 스크립트를 통해 Codex를 부르기로 했다. 명세를 쓰기 전에, 실제로 해 봐야 아는 7가지를 임시 저장소에서 확인했다.

- 임시 저장소: `LLM_Project/codex-probe` (함수 하나와 테스트 하나짜리 Python 저장소, 비교용이 아니라 버리는 저장소다. 삭제는 사용자가 한다.)
- 호출 방법: 공식 스크립트 `codex-companion.mjs task`, 그리고 같은 플러그인의 내부 라이브러리 `lib/codex.mjs`의 `runAppServerTurn`을 직접 부르는 시험용 스크립트
- 결과물은 모두 버린다. 버전 고정은 하지 않은 상태에서 시험했다.

## 항목별 상세

### 1. 파일 수정, 테스트, 커밋

`task --write`(저장소 폴더 쓰기 허용)로 "테스트 먼저 쓰고, 구현하고, 커밋하라"고 지시했다.

- 테스트 추가 → 실패 확인 → 구현 → 통과 확인까지 했다. 변경 내용도 지시와 같았다.
- 커밋은 `fatal: Unable to create '.../.git/index.lock': Permission denied`로 실패했다. Codex 샌드박스가 저장소 폴더 쓰기를 허용해도 `.git`은 막는다.
- Codex는 지시대로 멈추고 `STATUS: BLOCKED`와 오류 원문을 보고했다.

### 2. 한글

- 결과의 Codex 최종 메시지에 한글이 깨지지 않고 들어 있었다.
- Codex가 명령을 실행하는 셸은 Windows PowerShell 5.1이다.
- UTF-8로 출력하는 Python 명령을 그대로 실행하면 정상이고, `| Select-Object -First 1`로 파이프에 넘기면 `?�이???�험`처럼 깨졌다. 시범 프로젝트(usage-log-summary)에서 사용자가 확인한 문제와 같다. 원인은 PowerShell이 파이프로 받은 출력을 콘솔 인코딩(cp949)으로 해석하기 때문이다.

### 3. 대화 이어가기

- 명령줄의 `--resume`은 `--resume-last`의 다른 이름이다. 대화 ID를 지정하는 옵션은 없다.
- 같은 플러그인의 내부 라이브러리 함수 `runAppServerTurn(cwd, { resumeThreadId })`는 대화 ID를 받는다. 1번 시험의 대화 ID로 이어가자 같은 ID가 돌아왔고, 앞 대화에서 출력한 한글 문장과 추가한 함수 이름을 정확히 답했다(4초).
- 없는 ID를 주면 `no rollout found for thread id ...` 예외가 난다.
- 대안: 명령줄의 `task-resume-candidate --json`이 `--resume-last`가 고를 대화 ID를 보여 준다. 이 값이 기대한 ID와 같은지 확인한 뒤 `--resume-last`를 쓰면 같은 대화인지 검증할 수 있다.

### 4. Codex 쪽 Superpowers

- Codex가 스스로 `using-superpowers`, `test-driven-development`, `verification-before-completion` 스킬을 불러 썼다.
- 지시문에 "설계는 승인됐다, 질문하지 말라"를 넣었고, 설계 질문이나 브레인스토밍 없이 바로 구현했다.

### 5. 실패 판별

- **Codex가 막혀도 종료 코드는 0이다.** 1번 시험에서 Codex가 `STATUS: BLOCKED`를 보고했지만 결과의 `status`는 0이었다. 종료 코드는 "Codex의 차례가 정상으로 끝났다"는 뜻일 뿐이다.
- 없는 모델을 지정하면 종료 코드 1이 나온다. 그런데 `--json` 결과에는 `status: 1`과 빈 출력만 있고 오류 메시지가 없다. 일반 출력에는 오류 원문(`The 'no-such-model-xyz' model is not supported ...`)이 있다. 내부 라이브러리는 결과에 오류 필드를 함께 돌려준다(코드로 확인, 직접 시험은 안 함).
- 한도 도달은 재현하지 못했다. 7번의 세션 기록에 한도 도달 종류(`rate_limit_reached_type`)와 사용률이 있어서, 이 값으로 판별할 수 있을 것으로 본다(미검증).

### 6. 긴 작업과 명령 실행 제한 시간

- 함수 하나를 추가하는 작업이 208초 걸렸다. Claude Code의 명령 실행 기본 제한 시간은 120초, 최대 600초다.
- 공식 스크립트의 백그라운드 실행이 된다: `task --background` → 작업 번호 즉시 반환 → `status <작업 번호> --wait` → `result <작업 번호> --json`으로 최종 메시지와 대화 ID를 받는다. 다만 이 경로로는 대화 ID를 지정해 이어갈 수 없다.
- Claude Code의 백그라운드 실행(명령이 끝나면 Claude에게 알림이 옴)으로 내부 라이브러리 호출을 돌리는 방법도 된다. 150초 동안 기다리는 명령을 대화 ID로 이어간 대화에서 실행시켰고, 170초 뒤 제한 시간에 끊기지 않고 끝났다. 같은 대화 ID가 돌아왔고, 출력 `긴 작업 끝`도 깨지지 않았다. 이 방법은 대화 ID 지정과 백그라운드 실행을 함께 쓸 수 있다.

### 7. 사용량(토큰)

- 공식 스크립트의 결과에는 토큰 정보가 없다.
- Codex 세션 기록 `~/.codex/sessions/YYYY/MM/DD/rollout-*-<대화 ID>.jsonl`의 `token_count` 이벤트에 누적 토큰이 있다. 대화 ID가 파일 이름에 들어 있어서 래퍼가 바로 찾을 수 있다.
- 같은 이벤트에 한도 사용률도 있다: 5시간 한도(`primary.used_percent`), 주간 한도(`secondary.used_percent`), 초기화 시각, 한도 도달 종류. 사용자가 Codex 사용량을 직접 읽어 줄 필요가 없어진다.
- 참고: 1번 작업 하나에 총 34.5만 토큰을 썼다(그중 캐시 입력 32.2만). 작업은 작아도 스킬과 저장소를 읽는 기본 비용이 크다.

## 설계에 반영할 제안

1. **래퍼는 Node로 만든다.** 대화 ID로 이어가려면 플러그인의 내부 라이브러리를 불러야 하고, 그 라이브러리가 Node 모듈이다. 플러그인을 직접 부르는 곳은 래퍼 한 곳뿐이다.
2. **커밋은 래퍼가 한다.** Codex가 `DONE` 또는 `DONE_WITH_CONCERNS`를 보고하면 래퍼가 Codex가 바꾼 파일을 커밋한다. Claude는 코드를 고치지 않는다는 기준과 충돌하지 않는다.
3. **실패 판별은 세 겹으로 한다.** 래퍼 호출 실패나 예외, Codex의 오류 필드, Codex가 보고한 상태 줄을 모두 본다. 한도 도달은 세션 기록의 한도 정보로 확인한다.
4. **Codex는 Claude Code의 백그라운드 실행으로 래퍼를 돌린다.** 짧은 작업도 120초를 넘기 때문이다. 공식 스크립트의 백그라운드 실행은 대화 ID를 지정할 수 없어서 쓰지 않는다.
5. **사용량은 래퍼가 기록한다.** 호출마다 대화 ID, 토큰, 주간 한도 사용률을 남긴다.
6. **Codex 지시문에 PowerShell 파이프 주의를 넣을지는 3단계 비교 시험의 관찰 항목으로 둔다.** 2단계 명세 자체에 인코딩 요구가 없어서, Codex가 이 문제를 스스로 겪고 처리하는지 보는 것도 비교 거리다.

### 1차 실행: 8개 중 6개 통과

- **6번 샌드박스 경계 실패:** 저장소 밖 쓰기와 `.git` 쓰기는 거부됐지만 네트워크 접속(example.com:443)이 허용됐다. 세션 기록의 샌드박스 설정은 `network_access: false`였다. 원인은 Windows `unelevated` 샌드박스가 네트워크를 환경 수준으로만 제한하는 것이다(OpenAI 문서: 네트워크 격리가 약함). 방화벽으로 막는 `elevated` 방식은 관리자 승인이 필요하다.
- **8번 시간 초과 중단 실패:** 래퍼가 30초 뒤 차례를 중단했고 Codex도 `turn_aborted`를 기록했다. 하지만 그 차례가 띄운 Python 명령(90초 대기 후 파일 쓰기)은 계속 돌아 래퍼 종료 76초 뒤 `late.txt`를 만들었다. Windows에서는 차례를 중단해도 명령 프로세스가 끝나지 않는다.

### 사용자 결정과 대응

- 네트워크: 알려진 한계로 받아들인다. 래퍼가 세션 기록에서 네트워크를 쓰는 명령을 찾아 경고로 남긴다(탐지만 함). 5단계 전에 `elevated`를 다시 검토하되, 이 PC는 `elevated` 샌드박스가 Temp 폴더 권한을 망가뜨린 이력이 있으므로 복원 지점을 먼저 만든다.
- 시간 초과: 래퍼가 중단 직후 저장소 상태를 기록하고 2분 뒤 다시 비교해 바뀐 파일을 `lateChanges`로 남긴다. 종료 코드 3이면 마스터는 다시 시작하지 않고 그 목록과 함께 보고한다.
- 점검 항목을 9개로 바꿨다: 6번은 파일 쓰기 경계만 판정하고 네트워크는 기록만, 7번 네트워크 명령 탐지 추가, 9번은 중단 성공과 늦은 변경 탐지를 확인한다.
